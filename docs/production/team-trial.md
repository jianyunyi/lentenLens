# 团队试用与长期性能验收协议

状态：试用准备继续推进；Windows/Linux CI 与候选包已在 main 3475922 验证通过。真实团队试用、Windows 目标机器测量与长期观察均 NOT RUN。不得把合成回归当成用户验收。

## 进入条件
- 可靠性 PR 通过代码审阅，Windows/Linux CI、候选包内容校验通过。
- 试用者确认代码范围、模型服务商地址、密钥环境变量及 token 预算；默认先用无模型模式。
- 以已备份、受信任的小型项目开始；先关闭应用功能做只读观察。练习不是 OS 沙箱，不用于执行不可信代码。
- 由项目所有者选择参与者并取得同意；本任务未发送邀请、未联系任何人。

## 建议安排（计划，不是已执行事实）
选择 3–5 位目标用户，至少覆盖 Windows x64、本地 CLI 和 VS Code。建议先观察 2 周，再决定是否扩大；具体参与者、日期和性能阈值在试用开始时填写并冻结。

| 步骤 | 操作 | 必须记录 |
| --- | --- | --- |
| T1 安装/升级 | 安装 CI 校验候选包，停止旧进程后升级 | 包摘要、版本、系统/Go/VS Code 版本；安装失败 |
| T2 阅读/捕获 | 小/中/大三类真实工作区；开始、修改、停止、查看证据 | 文件数、捕获字节、索引遗漏、错误；不采集源码 |
| T3 恢复 | 只在一次性 fixture 强退进程、损坏单条历史记录 | 是否可恢复、是否误覆盖；不能破坏真实项目做故障实验 |
| T4 模型/共享 | 单独确认发送；纠错、修订、共享预览、取消 | 可核对的错误解释、用户纠错率、用量；不上传密钥/代码 |
| T5 练习/应用 | 受信任小包；验证、评分、冲突、明确确认应用 | 误通过、执行挂起、冲突处理、任何源码损坏 |
| T6 长期增长 | 每天记录历史数量、状态目录大小、命令时延与退出错误 | 每周对比相同机器/数据规模，观察增长趋势 |

## 复跑命令
```bash
go test ./... -count=1
go test ./internal/app -run '^$' -bench 'Benchmark(IndexWorkspace|InspectWorkspace|RoundHistory)' -benchmem -count=5
go build -trimpath -o /temporary/path/intentlens ./cmd/intentlens
node scripts/soak.cjs /temporary/path/intentlens 1000
```
Windows 使用 `.exe` 路径。soak 自动创建/清理一次性项目，不启用模型，不触碰用户真实项目。采集的是命令总时延和最终状态大小；harness RSS 不是 CLI 的峰值内存。进程被外部强杀后可能留下系统临时 fixture，测试人员可在确认无活跃进程后清理对应目录。

## 退出与回退
若出现数据完整性或隐私缺陷，停止模型发送与源码应用，保留私有备份，先修复/复验。回退前先处理应用恢复日志，并停止所有版本进程。记录问题编号、严重度、最小复现、受影响版本和重测结果。后续是否公开发行另行决策。

## S5 性能采集入口
在仓库根目录执行 `node scripts/history-acceptance.cjs 1000`。要求 PATH 中有 Go 和 Git；输出到被 gitignore 排除的 history-acceptance/：environment.json（提交、dirty 标记、实际源码树摘要、系统/CPU/Go）、benchmark.txt（20/200/1000 轮、含解释/纠错和无解释、各三次）、soak.json（1000 轮合成 CLI、二进制摘要、分位数）。CI 在 Windows/Linux 使用 100 轮快速版本，原始 artifact 保留 30 天。
此入口不读取实际业务工作区、不调用模型、不发送报告。它只能提供合成数据；T2/T4/T5 的人工体验、安装目标 VS Code、真实源码误解释与长期稳定性仍需实际执行。
目标机器正式试用启动前需填写：参与者代号与同意、Windows/Go/VS Code 版本、候选包摘要、只读试用仓库范围、起止日期、同机初始基线和性能预算。阈值由真实基线冻结，不采用 CI 虚拟机时延作为统一 SLA。
