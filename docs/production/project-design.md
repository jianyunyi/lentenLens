## 方案与失败路径
- 使用持久锁文件上的 OS advisory lock，永不在解锁时 unlink，避免两个 inode 同时持锁。Unix flock、Windows LockFileEx，其他平台失败关闭。旧二进制不理解新锁，升级要求停止所有旧进程，禁止混用。
- 启动在 capture 锁内检查历史记录的 JSON 类型；坏历史记录移动至 0700 私有 quarantine。配置、用量、应用日志不自动重置。隔离区不被读取/共享/发送模型；排除规则变化清除隔离原文，避免保留无法解析的撤销内容。
- 源码写入前将完整 before/after、策略摘要落盘到 apply-journal.json；同目录随机临时文件写完 Sync 后通过 Root.Rename 替换。进程中断后幂等回滚；如果当前内容既非 before 也非 after，保留外部修改和日志，失败关闭待人工处理。日志不是跨文件原子事务；独占应用锁仅协调本工具，比较与 Rename 间没有跨工具 CAS，应用时暂停并发编辑。
- 最低 Go 提升至 1.25：使用标准库 Root.Rename 保持路径约束，避免自行实现不安全的绝对路径替换。发行工具链固定值不变；普通练习模块仍可为 Go 1.24。
- 文件/目录 Sync 在支持的平台执行；Windows 文件替换不承诺所有文件系统上的断电原子性。验收覆盖进程中断，不把它等同于断电恢复。
- 轮次、Inspect、ExplanationByID 调用同一 freshness 规则；源码应用使用 Go-only 捕获。模型范围、token 预算和共享确认不变。
