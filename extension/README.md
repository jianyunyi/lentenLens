# IntentLens for VS Code

0.5.2 修复嵌套工作树或缓存挤占真实 Go 源码索引预算的问题。默认排除 `.worktrees`、`.cache`、`.pnpm-store`；Go 索引的 16 MiB 预算仅计算 Go 源码，单文件上限仍为 1 MiB。普通轮次仍捕获允许范围内的一般文本。把某个 worktree 本身作为工作区根打开时，其源码仍可索引。

索引不完整或 CLI 失败时，函数文件顶部保留诊断 CodeLens，状态栏提供入口，不再静默消失。运行 **IntentLens: 查看索引范围与遗漏原因** 查看 Go 源码预算、遗漏/排除计数和最多 20 个遗漏示例；排除路径不会被列出。函数详情和内联标题也提示范围限制。诊断只读、不调用模型、不修改 `.intentignore` 或工作区设置；源码变化关闭当前源码详情/诊断，历史轮次快照不受影响。

本地 Go 函数证据、按轮次保存的工作区净变化，以及可配置厂商的模型解释。需要 VS Code 1.90+ 和 IntentLens CLI，不要求 Claude Code。没有 npm 运行时依赖。除 IDE 扩展外，也可通过项目提供的 IntentLens Skill 调用相同 CLI。

## 启动

1. 在扩展 `bin/` 放置对应平台的 `intentlens.exe` / `intentlens`，或将 CLI 加入 PATH；也可配置 `intentlens.binaryPath` 为可执行文件路径（不接受 shell 参数）。
2. 打开并信任本地 Go 工作区。多根工作区按文件所属根目录分析；项目级命令会让你选择根目录。
3. 保存 Go 文件，点击函数上方 `IntentLens · 在函数下方展开解释`，或执行 `IntentLens: 查看当前函数解释与证据`。当前分析依据磁盘版本；未保存文件不展示 CodeLens。
4. 修改前执行“IntentLens: 开始记录本轮修改”，修改并保存后执行“IntentLens: 结束记录本轮修改”。可使用任何编码代理或手工修改，不需要 Claude。只记录磁盘内容，结束操作不自动调用模型。
5. Explorer 中展开 `IntentLens · 轮次`。点击轮次查看净变化、before/after 快照与已保存分析；IDE、Skill / CLI 和可选 hooks 共享同一捕获规则，不能为同一工作区重叠开启轮次。
6. 重载或其它工具启动的轮次可用“IntentLens: 恢复未结束的轮次”关联当前基线，保存后再结束；确认其它工具没有继续使用它。若决定放弃记录，用“IntentLens: 取消当前轮次（保留源码）”。这些命令也在轮次视图标题菜单中。
7. 需要模型解释时，在轮次面板点击“生成轮次解释”并确认。已有解释时显示“重新生成轮次解释”；旧解释保存在本地历史，新解释成为本轮展示版本。失败保留原显示，不自动重试。

## 从源头查看调用路径

保存 Go 文件，把光标放在函数内，点击活动栏的 IntentLens 调用图标，再点击“显示当前 Go 函数的调用路径”；也可执行 **IntentLens: 显示调用路径**。树从索引范围内的候选源头开始，展开到当前函数及其下游。视图标题中的刷新按钮按当前光标重新加载。函数节点可打开声明，调用节点显示源码文件、物理行号和原始调用表达式，点击定位到调用点。

这是本地源码证据路径，不是模型的隐藏思考或运行时轨迹，不请求模型。仅沿同目录同包内唯一解析的直接静态调用扩展；歧义目标保留为候选，跨包、接口及动态调用可能未知。环使用明确标记的组件代表，不把它称为真实入口。图最多 200 个函数、1,000 个调用点，树最多展示 2,000 次节点出现；达到上限会提示截断，不能视为整项目完整链路。

路径焦点为当前函数的全部可识别上游与下游，不把上游的无关兄弟分支或共享下游的其他调用者混入其中；这些函数的调用点证据仍会保留，范围外目标明确标记。源码或排除规则变化后重新加载；跳转前再次核验本地证据，多根工作区保持原图所属根目录，未保存的目标文件会阻止跳转。

CLI 对应命令为 `call-path`，输入与 `inspect` 相同：`{"file":"main.go","line":12}`。开发时在仓库根目录运行 `scripts/callpath-oracle-benchmark.sh /tmp/callpath-metrics.json`，以及 `node scripts/callpath-acceptance.cjs /absolute/path/to/intentlens`。这两项仅测试已知答案的合成源码，不测量真实模型回答准确率。

## 查看本地模型回答与证据

在 Activity Bar 的 IntentLens 容器中打开 **模型回答与证据**，并将光标放在已保存的 Go 函数中。面板只读显示该函数本地保存的解释历史、结论状态、未确定项和引用证据；点击引用可打开生成时保存的源码快照。移动光标或切换文件后，面板按新的函数刷新。

打开或刷新面板不会生成回答、联网或发送模型请求。没有已保存解释时会明确显示空状态；如需生成解释，请使用现有的显式命令和确认流程。

## Skill 与其它 IDE

源码仓库的 `.cursor/skills/intentlens/SKILL.md` 提供显式 Skill 入口；其它宿主按自己的目录约定加载同一个 Skill。Skill 和能启动本地进程的 IDE 可运行 `intentlens integration-info` 获取 JSON 协议，调用 `capture-event`、`inspect`、`rounds` 等。这里只交付 VS Code 原生扩展及通用 CLI，不声称所有 IDE 已有原生扩展。

读取本地证据和记录变化不需要模型密钥；Skill 宿主自行组织的回答不是 IntentLens 已保存或支持检查过的解释。需要保存检查版解释时，仍须按下面的流程同意项目模型接收地址、范围和预算。

## 解释任意代码选区

在任意代码语言的编辑器里选中一段代码，右键选择 **IntentLens: 解释选中代码（作用、流程与设计考虑）**；也可从命令面板运行同名命令。结果显示在编辑器旁的临时解释面板。空选区会提示先选择代码；`plaintext` 语言模式不作为代码处理，请先切换到相应语言。单次选区上限为 16 KiB。

该命令复用当前工作区已配置的模型 provider、SecretStorage 密钥、token 预算和复核模式。必须先保存文件；脏缓冲区会被拒绝。只读取保存版本中与选区相交的 VS Code Error 级诊断，不包含 warning、info、hint 或选区外错误。扩展仅将当前文件相对工作区的路径交给本机 CLI，用于在任何模型调用前应用默认排除规则和 `.intentignore`；该路径不会进入模型请求。发给模型的内容只有所选代码、VS Code 语言标识、选区坐标及这些错误诊断的原始消息和位置；不会发送未选中的同文件内容或仓库上下文。诊断消息按不可信数据处理，不会作为指令。结果由一个对象统一返回解释 claims、错误诊断、未知项和证据；诊断位置同时提供文档绝对位置和相对选区位置，行列从 1 起始，列以 VS Code UTF-16 代码单元计，区间末端不包含在范围内。回答和选区只在当前临时面板中显示，不写入源码、本地解释历史或仓库。模型可能记录请求，避免选择密钥或其他不应外发的内容。

解释按意义/可能用途、可见输入输出与副作用、执行流程和可能的设计考虑组织。设计考虑会标为合理推断，不声称知道原作者真实动机；选区不足以判断的上下文会列为未知。新功能实现只按选区中实际展示的机制说明，不假设周边实现完整。

开发测试：在仓库根目录运行 `go test ./...`；再进入 `extension/` 运行 `npm test` 和 `npm run check`，不需要 `npm install`。可在 VS Code 中打开 `extension/` 文件夹并按 F5 启动 Extension Development Host；确保 CLI 在扩展 `bin/` 或 PATH 中，并在真实工作区中配置模型后再验证实际网络请求。自动化覆盖使用 mock，不代表真实 Extension Host 或真实 provider 已通过验收。

## 可选模型分析

默认在函数结束行下方打开可折叠解释区域，按作用、为什么这样写、依据、依赖组织。不修改源文件；生成与追问使用原有配置和预算。没有模型解释时明确提示尚未生成；缺乏设计动机证据时明确未知。点击“完整详情与历史”进入原详细面板查看共享、修订和旧版本。

源码或排除规则变化会移除内联内容，保存后重新点击加载。旧解释不会自动重写，需主动重新生成才能获得新的内容组织。

默认只有本地证据。执行 `IntentLens: 启用或调整模型分析` 后选择 OpenAI、Anthropic、Gemini、DeepSeek、通义千问或其他兼容服务，填写 Base URL 并在密码输入框输入 API Key。确认后，扩展只向所选地址的 `GET /models` 发送模型列表请求；Key 仅放在该 provider 的认证请求头中，不传项目代码。模型 ID 必须从此次返回项中选择，不能手动填写或跳过查询；失败、空列表或取消都不保存。最终确认后 Key 存入 VS Code SecretStorage，配置文件只存模型 ID 与安全环境变量名。设置项目累计 token 上限并选择复核策略（默认 `light`）。切换厂商不清空预算。`fast` 仅用于小范围且不做独立复核；较大输入自动升级为 `strict`。完整阈值说明位于项目源码的 `docs/verification-modes.md`。

基础地址不含末端 `/models`、`/chat/completions` 或 `/messages`，远程必须 HTTPS，本机 loopback 可 HTTP。Gemini 选择器保留 API 返回的 `models/<name>` 资源 ID。模型服务须支持对应文本协议和用量字段；不保证任意厂商/模型可用。当前不支持 Azure 部署专属路径、Responses-only、Bedrock 签名、Vertex OAuth。未知用量保留未决占用，没有自动重试。旧 Anthropic 配置继续兼容；真实账户未实测。

函数面板支持生成解释和自由提问。解释按 claim 展示证据引用与 supported / unsupported / uncertain 状态，保留模型未能确认的内容。模型支持检查也可能出错。查看状态命令显示实际 token、保守未决占用与 CLI 返回的费用说明；token 上限不是货币费用上限。暂停命令阻止新的分析，已经发出的请求可能仍完成。

## 团队共享与纠错

具体说法旁可标记“有误 / 证据不支持”，原因仅保存在本地。生成修订保留旧版本并创建新版本；修订仍需人工核对。

“准备共享”仅依据获准证据重新生成，计入项目模型预算。私有证据默认不选。完整预览后点击确认，才写入 `.intent/shared/<id>.json`；关闭或取消不会写入。预览后依据或排除规则变化会拒绝确认，不自动 Git 提交或推送。

执行“IntentLens: 查看团队共享解释”读取仓库记录，无需作者本地状态。接收者点击“本地纠错与修订”保存本地副本后可标错、修订；个人理由不进入共享记录。修订须重新预览共享，原共享版本保持不变。本地标错不会自动通知其他成员。

## 小修改练习

行为说法旁可主动生成练习。先核对题目要求，再预览 Go 命令、目录和范围并确认验证；同题相同范围可以重复执行。验证区分原测试、基线预期失败与参考修改通过，参考修改不在界面展示。

打开仓库外作答文件，保存后评分。行为检查、实际测试结果和模型理由反馈分别展示；模型不能覆盖失败。改动固定测试会拒绝评分，需新题目版本。原项目应用必须先预览，发生冲突停止。

通过命令查看本地练习或团队题目。题目共享需完整验证和预览，不包含参考解、答案、成绩、理由与授权；接收者本地没有参考解，因此不冒称完成本地三项验证，保留暂定评分。

当前版本的题目验证、评分和 `exercise-run` 均已关闭：没有经过验证的 OS 沙箱，CLI、旧授权或 UI 操作都不会启动 Go 测试代码。题目仍可查看和编辑答案；禁用执行不等于沙箱能力已实现。

## 可选 Claude Code hooks

执行 `IntentLens: 预览 Claude Code Hook 配置`，将生成的 UserPromptSubmit / Stop 配置手动合并到 Claude Code 设置，保留已有 hooks。扩展不会修改设置文件。CLI 必须在 Claude Code 进程的 PATH 中；扩展的 binaryPath 设置不会配置该 PATH。启用模型后 Stop hook 可触发远程轮次分析。

这只是可选适配器。不使用 Claude 时无需执行此步骤，也不要与 IDE 手动入口为同一轮重复建立基线。

## 证据语义与限制

- 历史证据原文打开已捕获的文本，当前文件按钮打开现在的文件，两者可能不同。所有当前文件导航验证路径位于真实工作区内，包括符号链接目标。
- 静态 Go 索引保守处理调用关系，不执行构建，不下载依赖，不能解析所有动态调用。缺失证据、无法唯一解析的目标会显示为分析限制。
- 轮次表示工作区变化，不能单凭结果确认变更作者或作者动机；测试源码不能证明测试已执行。
- CLI 遵循其排除策略。监视到 `.intentignore` 新建、修改或删除（含外部编辑）时，关闭受影响工作区的证据/轮次面板、刷新列表并应用持久化隐私清理。每次证据导航和分析前重新读取策略允许的证据；内容变化时先刷新面板，请重新选择操作。已经手动打开的历史快照文本是独立编辑器文档，需要自行关闭。
- 本扩展只支持本地文件工作区。CodeLens 每次请求重新调用本地索引，大型仓库可能有延迟。
- 自动化测试覆盖 CLI JSON 桥接、选区解释最小化 payload、HTML/CSP、路径约束、共享确认和接收者纠错。选区解释的测试使用 mock 模型响应；真实模型与 Claude 会话仍待实测。

运行 `npm test` 与 `npm run check` 验证，不需要 `npm install`。
